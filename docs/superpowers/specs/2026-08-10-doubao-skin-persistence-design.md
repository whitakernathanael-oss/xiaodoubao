# 豆包皮肤持续恢复设计

## 目标

用户应用主题后，即使关闭皮肤工具、关闭并重新启动豆包，皮肤也自动恢复。用户可在皮肤工具内关闭此能力，或点击“恢复官方外观”。

## 范围

- 保存当前生效主题 ID、豆包路径、CDP 端口和自动保持开关。
- 皮肤工具关闭后，独立守护进程继续运行。
- Windows 登录后，守护进程自动启动。
- 守护进程只通过 `127.0.0.1:9225` CDP 连接豆包；无调试端口时不强杀进程。
- 守护进程检测到豆包未运行时，用保存的路径和 `--remote-debugging-port=9225` 启动豆包。
- 页面重载、CDP 重连、豆包重启后，重新应用已保存主题。
- 不增加托盘菜单。主界面设置区仅保留“自动保持皮肤”开关和状态文案。

## 非目标

- 不注入未带 CDP 端口启动的豆包。
- 不结束用户正在使用的豆包进程。
- 不新增主题编辑能力、云同步、付费或社区功能。

## 方案

使用单独的 Node 守护入口，而不是让 Electron 主窗口隐藏常驻。应用主题时写入 `active-skin.json`，内容包括主题 ID、端口、可执行文件路径及启用状态；随后启动守护进程。守护进程以固定间隔探测 CDP；豆包不运行时带调试参数启动；端口可用后复用 `SkinWorkflow` 应用主题。`Injector` 已监听 `Page.loadEventFired`，因此渲染器页内重载继续重注入。

Windows 登录启动使用当前用户 Startup 快捷方式，目标为打包后的应用 `--skin-guardian` 模式。该模式不创建可见窗口，仅启动守护进程。关闭开关、恢复官方外观、删除当前主题时，写入禁用状态并停止守护；关闭皮肤工具窗口不停止守护。

## 安全与故障处理

- 仅使用回环 CDP。
- 主题、壁纸继续从本地 ThemeStore 读取。
- 连续失败使用退避，避免反复启动豆包。
- 豆包已运行但没有 9225 时，守护不终止它；状态记录“等待用户重启豆包”。
- 恢复官方外观会先尝试清除当前注入，再禁用后续自动恢复。

## 验收

1. 应用主题后关闭皮肤工具，当前豆包界面仍保留皮肤。
2. 关闭豆包，守护使用保存路径启动带 9225 的豆包，并恢复同一主题。
3. 豆包页面重载后，主题重新注入。
4. 关闭“自动保持皮肤”或恢复官方外观后，守护停止，不再自动应用。
5. 豆包已正常启动但未开放 9225 时，守护不结束豆包且给出明确状态。
