# 壁纸上传自动保存主题设计

## 目标

用户选中一张静态壁纸后，工具立即从图片生成单一种子色主题并保存为自定义主题；无需再点击“保存主题”。同一规范化文件名再次上传时，覆盖原有同名自定义主题，而不是创建 `Copy`。

## 范围

- 支持现有 PNG、JPEG、WebP 壁纸选择流程。
- 保持现有调色算法、主题目录格式、ZIP 导入导出格式和“应用到豆包”行为不变。
- 不自动将主题应用到豆包；用户仍通过“应用到豆包”决定何时注入。
- 保留“保存主题”按钮，供用户修改壁纸位置、缩放、模糊或亮度后手动保存。

## 行为

1. 用户选择图片；取消选择时不改变当前主题。
2. 渲染进程先提取调色板并显示本地预览。
3. 以 `WallpaperSelection.name`（主进程已规范化的文件名）在已加载的主题摘要中查找 `readOnly: false` 且 `wallpaperFile` 相同的主题。
4. 如果找到匹配主题：加载该主题作为保存基底，替换其壁纸文件和派生色板，保留其 ID、名称以及用户已调过的壁纸布局参数。
5. 如果未找到匹配主题：以 `DEFAULT_THEME` 为基底，生成唯一的用户主题 ID，主题名称使用去扩展名后的图片文件名；随后写入壁纸文件和派生色板。
6. 调用既有 `api.saveTheme({ theme, wallpaper: selection })` 立即保存图片字节和 `theme.json`。
7. 保存成功后刷新主题列表，选中新主题，清除待保存壁纸标记，并显示“已自动保存”状态。
8. 调色或保存失败时保留当前预览和待保存图片，显示错误；用户可点击已有“保存主题”按钮重试。

## ID 与覆盖规则

- 覆盖只匹配用户主题；内置主题永不写入。
- 新 ID 为 `wallpaper-<文件名词干的 ASCII slug>`。slug 为空时使用 `wallpaper-theme`。
- 如果新 ID 已被另一主题占用，则追加 `-2`、`-3` 等后缀，直至可用。
- 同名覆盖以 `wallpaperFile` 的完整规范化文件名为准，因此 `scene.png` 和 `scene.jpg` 是不同主题。

## 实现边界

- 修改 `src/renderer/app.ts`：把选择壁纸后的临时编辑流程替换为“准备主题 → 预览 → 自动保存”的异步流程，并新增小型 ID/文件名辅助函数。
- 修改 `tests/renderer.test.ts`：覆盖首次上传、新建 ID、同名覆盖、保存参数、失败后保留重试状态。
- 不修改主进程 ThemeStore：其现有原子保存已经可安全覆盖用户主题。

## 验收标准

- 上传 `003.jpg` 后，左侧立刻出现名为 `003` 的自定义主题，关闭并重开工具后仍存在。
- 再上传同名 `003.jpg` 后，自定义主题数量不增加，原主题 ID 被保存覆盖。
- 上传不同文件名图片后，创建新的自定义主题。
- 上传失败或提色失败时，不写入半成品主题，预览仍可见且可手动保存重试。
- 选择壁纸不会自动应用到正在运行的豆包。
