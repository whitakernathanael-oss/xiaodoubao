# 单图自动取色与可靠发布设计

## 目标

豆包皮肤版 MVP 面向普通用户只保留一条主要路径：选择一张本地图片，应用自动提取的配色，然后将主题应用到豆包。开发者仍可在应用外制作精美主题 ZIP，普通用户只需导入成品，不在应用内提供高级主题编辑器。

本轮同时完成四项优化：可靠的 Windows 发布命令、注入后的验证与失败回滚、把自动取色接入真实豆包样式、删除界面简化后遗留的无用代码。

## 范围

### 包含

- 单张 PNG、JPG、JPEG 或 WebP 壁纸选择。
- 从图片提取 `accent`、`surface`、`ink` 和 `mutedInk`。
- 自动配色只作用于强调色、选中状态、按钮、边框和对比度安全遮罩。
- 豆包正文和系统控件文字颜色继续跟随豆包与 Windows 的深浅模式，不由皮肤强制覆盖。
- 主题注入后进行真实验证；失败时删除本次注入并恢复官方外观。
- 一个 Windows 正式发布命令，自动检查、测试、清理旧构建并重新生成安装包。
- 保留开发者主题 ZIP、可选 `extra.css`、适配器、导入导出和三个内置主题。
- 删除不再被界面或运行流程使用的状态、IPC、变量和重复探测代码。

### 不包含

- 多张装饰图片、贴纸、字体、JavaScript 或插件。
- 应用内高级调色器或 CSS 编辑器。
- 主题商店、在线 Studio、账户、付费、云端 API 或自定义 URL 协议。
- 托盘常驻、后台 watchdog、自动更新和 macOS 支持。
- 改写豆包安装文件、`app.asar` 或用户数据。

## 用户路径

### 普通用户

1. 选择一个内置主题作为安全样式基础。
2. 点击选择图片。
3. 应用读取图片并自动提取配色。
4. 本地预览显示壁纸、裁切位置和安全配色。
5. 用户保存或应用主题。
6. 应用连接豆包、注入、验证并报告结果。

普通用户不需要看见 `theme.json`、`extra.css` 或适配器。

### 使用开发者主题的用户

1. 开发者在应用外制作 ZIP。
2. ZIP 包含 `theme.json`、一张壁纸和可选 `extra.css`。
3. 用户点击“导入 ZIP”。
4. 应用验证格式、资源大小、CSS 作用域和安全规则。
5. 合法主题进入本地主题列表，之后与内置主题使用相同的预览、应用、验证和恢复流程。

适配器不放入主题 ZIP。适配器由项目维护者用于描述豆包各语义区域的 DOM 选择器；豆包升级导致结构变化时，只更新适配器。

## 组件与职责

### 自动配色

现有图片取色器继续负责产生基础 palette。新增一个纯映射函数，将 palette 转换为有限的安全主题字段：

- `accent` 用于选中状态、焦点边框和主要按钮。
- `surface` 只参与低透明度表面混色，不直接替换所有背景。
- 深浅判断用于选择黑色或白色安全遮罩基色。
- `ink` 和 `mutedInk` 可用于本地预览说明文字，但不得覆盖真实豆包的正文颜色。

该函数不读取 DOM，输入相同 palette 时输出必须相同，便于单元测试。

### 注入、验证与回滚

工作流只保留一次页面兼容性判断。注入器返回实际匹配到的区域和注入状态，工作流据此判断兼容、部分兼容或不兼容。

注入返回成功后，工作流调用 `verify()`，确认：

- 注入标记存在；
- 样式节点存在；
- 壁纸节点存在且挂载在目标聊天区域；
- 必需语义区域仍然可见。

任何验证失败都执行本次注入的 `restore()`。只有验证通过才向界面返回“应用成功”；恢复失败时返回明确错误，不报告虚假成功。

### Windows 发布

新增唯一正式发布命令 `npm run release:win`，顺序固定为：

1. `npm run typecheck`
2. `npm test`
3. 删除项目下的旧 `out` 构建目录
4. `electron-forge make --arch=x64`
5. 输出当前 `package.json` 版本和新安装包位置

删除范围只能是当前项目绝对路径下的 `out`。开发命令 `npm start` 不触发清理或打包。

### 代码精简

在行为测试覆盖下删除：

- 已无界面入口的撤销栈、`undo()` 和区域重置逻辑；
- 没有消费者的日志读取 IPC，保留日志写文件；
- 注入器与工作流之间重复的选择器预探测；
- 只赋值但不被 CSS 消费的变量；
- 所有项都固定为 `range` 的无效控制类型字段；
- 只检查生成源码字符串、但不验证真实行为的脆弱测试。

ZIP 安全校验、CSS 解析器、主题契约和适配器验证不属于可删除范围。

## 错误处理

- 图片格式或尺寸不合法：拒绝读取，不改变当前主题。
- 取色失败：保留当前主题和壁纸，显示可理解的错误。
- 豆包未启动或调试端口冲突：不尝试注入，显示现有连接错误。
- 必需区域找不到：报告不兼容，不把部分效果当作成功。
- 注入后验证失败：恢复官方外观并报告应用失败。
- 正式发布任一步失败：立即停止，不保留一个看似成功的新安装包结果。

## 测试与验收

### 自动测试

- palette 到安全主题字段的确定性映射。
- 明亮和深色图片都不会产生低对比度的安全遮罩组合。
- 注入成功且验证成功时返回应用成功。
- 注入成功但验证失败时调用恢复并返回错误。
- 恢复失败时不会返回应用成功。
- 删除重复探测后，兼容、部分兼容和不兼容状态保持一致。
- ZIP、`extra.css` 和适配器原有测试继续通过。
- `npm run typecheck` 和全部 Vitest 测试通过。

### 人工验收

- 分别选择一张亮图和一张暗图，实际豆包正文仍清晰可读。
- 自动提取的强调色能在选中项、按钮或焦点边框中看见。
- 应用主题、切换聊天、恢复官方外观均正常。
- 模拟验证失败时主题被清理，不留下半应用状态。
- 连续执行两次 `npm run release:win`，第二次安装包仍包含最新界面和版本。
- 新生成的 Setup.exe 可安装，新生成的便携目录可启动。
- 现有开发者主题 ZIP 仍能导入、预览、应用和导出。

## 完成标准

- 普通界面没有新增高级编辑入口。
- 一张图片能够驱动真实豆包的安全强调色，而不仅是本地预览。
- 应用成功状态有注入后验证证据，失败会恢复。
- Windows 正式发布不会复用旧 `out`。
- 四类遗留代码被删除且测试覆盖保持或增强。
- 开发者主题兼容性没有倒退。
