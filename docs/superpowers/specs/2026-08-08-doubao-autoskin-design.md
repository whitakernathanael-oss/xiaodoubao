# 豆包 AutoSkin MVP 设计规格

- 日期：2026-08-08
- 状态：已完成会话设计确认，待用户审阅书面规格
- 目标平台：Windows 10/11 64 位
- 对标项目：[Finderchangchang/codex-autoskin](https://github.com/Finderchangchang/codex-autoskin)

## 1. 背景与目标

豆包 Windows 客户端能够通过 `--remote-debugging-port=9225` 暴露 Chrome DevTools Protocol（CDP）。已观察到的目标包括主聊天页面 `doubao://doubao-chat/chat`、后台页面 `doubao://doubao-background/` 和跨站支持页面。该能力允许外部工具在不修改豆包安装文件的情况下，向经过允许的渲染页面注入 CSS 和少量受控运行时代码。

本项目要交付一个可自用、可继续开源迭代的 Windows MVP。用户可以选择静态壁纸，本地自动取色，通过鼠标调整豆包不同区域的颜色和样式，在简化预览中查看效果，然后应用到正在运行的豆包。工具同时支持主题 ZIP 的导入导出，以及一个可替换的豆包页面适配器。

工具本身完全开源，不包含账号、付费、授权验证、主题商城或功能限制。私人定制是一项独立服务：定制者交付与免费主题相同格式的本地主题包，用户用开源工具导入即可。

## 2. MVP 范围

### 2.1 包含

- Electron 单窗口 Windows 应用。
- 三个只读内置示例主题，分别演示明亮、深色和半透明区域风格；具体美术内容不是功能验收条件，但素材必须原创、授权或程序化生成。
- PNG、JPG、JPEG、WebP 静态壁纸。
- 本地自动取色和浅色/深色路线判断。
- 鼠标颜色选择器。
- 按区域调整壁纸、侧栏、聊天区、输入框、按钮/卡片和设置面板。
- 编辑器内简化预览；只有点击“应用到豆包”才执行 CDP 注入。
- 用户主题的新建、复制、重命名和删除。
- 标准 ZIP 主题包导入导出。
- 可选且严格限定作用域的 `extra.css`。
- 一个可替换的 `doubao-adapter.json`。
- “豆包皮肤版”桌面快捷方式。
- 一键恢复官方外观。
- 单个有大小上限的文本日志。

### 2.2 明确不包含

- GIF、APNG、视频或自动转码。
- 图形化兼容性诊断中心。
- 开机守护、系统托盘或自动恢复服务。
- 在线主题库、云同步、遥测或素材上传。
- 账号、支付、会员、许可证、DRM 或主题付费标识。
- 主题 JavaScript、插件系统或任意代码执行。
- 鼠标点选豆包任意 DOM 元素的检查器。
- 字体替换、图标替换、间距编辑和悬停动画编辑。
- 多版本适配器注册中心和在线适配器更新。

## 3. 技术选择

使用 Electron、TypeScript、原生 HTML/CSS 和浏览器原生控件。单窗口 MVP 不引入 React、Vue 或其他 UI 框架。

Electron 进程边界：

1. **渲染进程**：绘制主题列表、简化预览和样式控件，并使用 Canvas 完成本地自动取色。素材字节通过受限 IPC 获得；渲染进程不能直接访问文件系统、启动进程或连接任意 WebSocket。
2. **预加载脚本**：仅暴露经过枚举的主题、文件、启动、应用、恢复和状态查询接口。
3. **主进程**：负责豆包发现/启动、CDP、主题读写、ZIP、安全校验、日志和桌面快捷方式。
4. **豆包内注入运行时**：只处理语义标记、CSS 变量、壁纸层、页面变化和清理。

`BrowserWindow` 必须启用 `contextIsolation`、`sandbox` 和 `webSecurity`，禁用 `nodeIntegration`。编辑器不加载远程网页。

## 4. 总体架构

```text
Electron 编辑器渲染进程
        │ 受限 IPC
        ▼
Electron 主进程
  ├─ 主题与 ZIP 服务
  ├─ 豆包启动器
  ├─ CDP 客户端
  ├─ 适配器加载器
  └─ 日志
        │ 127.0.0.1 / ::1
        ▼
豆包允许页面
  ├─ 语义区域标记
  ├─ 主题 CSS 变量
  ├─ 静态壁纸 Blob URL
  └─ 清理入口
```

结构样式和主题数据分离。引擎维护一套只消费语义 CSS 变量和标记类名的结构 CSS；主题只能提供标准字段、壁纸和受限 `extra.css`，不能修改引擎代码。

## 5. 用户界面

主窗口采用单页三栏布局：

```text
顶部：豆包状态和当前主题
左侧：内置主题与用户主题
中间：聊天页/设置页简化预览
右侧：当前区域的样式控件
底部：撤销、重置区域、保存、恢复官方外观、应用到豆包
```

### 5.1 左侧主题列表

- 固定显示三个只读内置主题。
- 显示全部用户主题，不人为限制数量。
- 支持新建、复制、重命名、删除、导入和导出。
- 尝试修改内置主题时，先复制为用户主题。
- 导入出现同名主题时，自动添加 `-2`、`-3` 等后缀，不实现复杂合并界面。

### 5.2 中间预览

- 提供“聊天”和“设置”两个标签。
- 使用本项目维护的简化结构，不嵌入真实豆包页面。
- 控件变化立即反映在预览中，但不会自动注入豆包。
- 主题缩略图由当前壁纸和配置运行时生成，不作为主题包必需文件。

### 5.3 右侧区域控件

全部颜色选择优先使用浏览器原生颜色输入控件，数字使用滑块和数字输入组合。

- **壁纸**：文件、`cover`/`contain`、水平位置、垂直位置、缩放、模糊、亮度、遮罩颜色和遮罩透明度。
- **侧栏**：背景、透明度、文字色、选中项颜色、边框色、圆角。
- **聊天区**：背景透明度、用户气泡、豆包气泡、文字色、边框、圆角、阴影。
- **输入框**：背景、透明度、文字色、边框、圆角、聚焦色。
- **按钮与卡片**：主色、普通背景、文字色、边框、圆角、阴影。
- **设置页面**：沿用全局配色，并允许单独调整面板背景和透明度。

### 5.4 主要流程

```text
选择或新建主题
→ 选择静态壁纸
→ 本地自动取色
→ 鼠标调整区域样式
→ 简化预览
→ 保存
→ 应用到豆包
→ 验证关键区域
```

## 6. 主题格式

用户主题保存在 `%LOCALAPPDATA%\DoubaoSkin\themes\<id>\`。内置主题打包在应用资源中，保持只读。

```text
<theme-id>/
├── theme.json
├── wallpaper.png | wallpaper.jpg | wallpaper.jpeg | wallpaper.webp
└── extra.css（可选）
```

`theme.json` 的稳定顶层结构：

```json
{
  "formatVersion": 1,
  "id": "clean-light",
  "name": "Clean Light",
  "author": "Doubao AutoSkin",
  "wallpaper": {
    "file": "wallpaper.webp",
    "fit": "cover",
    "positionX": 50,
    "positionY": 50,
    "scale": 100,
    "blur": 0,
    "brightness": 100,
    "overlayColor": "#ffffff",
    "overlayOpacity": 0.1
  },
  "palette": {
    "ink": "#222222",
    "mutedInk": "#666666",
    "accent": "#4f7cff",
    "surface": "#ffffff"
  },
  "regions": {
    "sidebar": {},
    "chat": {},
    "composer": {},
    "buttons": {},
    "settings": {}
  }
}
```

具体区域字段由 JSON Schema 固定，未知字段在读取时忽略，以允许向后兼容；缺失字段使用引擎默认值。`formatVersion` 不受支持时拒绝导入，而不是猜测转换。

主题 ID 必须为小写 kebab-case。壁纸必须位于主题目录根部，不能引用绝对路径、父目录或远程 URL。单个壁纸最大 25 MB，最长边最大 4096 像素。

## 7. 自动取色

自动取色完全本地运行：

1. 使用浏览器图片解码能力读取素材。
2. 等比缩小到 64×64 色彩样本。
3. 忽略 Alpha 小于 96 的像素。
4. 每个 RGB 通道保留高三位，形成最多 512 个颜色桶。
5. 计算平均相对亮度；阈值 0.52 以上采用亮图路线，否则采用暗图路线。
6. 主色按“像素数量 ×（0.5 + 饱和度）”评分。
7. 优先选择与主色色相相差至少 40° 的高饱和颜色作为辅助色；找不到时从主色色相偏移生成。
8. 从有分量的最暗颜色派生文字墨色。
9. 生成强调色、表面色、文字色和区域透明度默认值；普通文字与背景的对比度目标不低于 4.5:1。

生成值只是起点。用户可以在右侧控件中修改全部可视化字段。

## 8. ZIP 导入导出与 CSS 安全

MVP 使用普通 `.zip`，不注册自定义扩展名和文件关联。

### 8.1 导入

- 在系统临时目录解压到随机子目录。
- 拒绝绝对路径、`..`、符号链接、嵌套压缩包和超出大小限制的条目。
- 只允许一个 `theme.json`、一张允许格式的壁纸和一个可选 `extra.css`。
- 禁止 HTML、JavaScript、可执行文件、字体和其他二进制文件。
- 完整验证通过后，原子移动到用户主题目录；失败不留下半成品。

### 8.2 导出

- 只打包标准主题文件。
- 不写入绝对路径、日志、豆包数据或本机设置。
- 导出的免费主题和私人定制主题没有格式差异，也没有 DRM 字段。

### 8.3 `extra.css`

- 每条选择器的第一个复合选择器必须锚定 `html.doubao-skin.theme-<id>` 或等价的 `:root` 主题作用域。
- 只允许普通规则、`@media` 和 `@supports`。
- 禁止 `@import`、`@font-face`、`url()`、远程资源和脚本相关构造。
- CSS 无效或越出作用域时，忽略整个 `extra.css`；标准主题仍可导入和使用。
- 壁纸和装饰层必须 `pointer-events: none`。

CSS 校验必须使用 CSS 语法树解析器，不能只依赖正则表达式。

## 9. 豆包启动与 CDP

默认检测路径：

```text
C:\Users\<用户>\AppData\Local\Doubao\Application\Doubao.exe
```

找不到时让用户手动选择并记住路径。

启动器按顺序：

1. 同时探测 `http://127.0.0.1:<port>/json/list` 和 `http://[::1]:<port>/json/list`。
2. 默认端口为 9225；端口被非豆包进程占用时不终止占用者，要求用户更换端口。
3. 豆包未运行时，以 `--remote-debugging-address=127.0.0.1 --remote-debugging-port=<port>` 启动。
4. 豆包已运行但没有 CDP 时，征得用户确认后关闭并重新启动；MVP 不静默强杀。
5. 读取目标列表并只连接适配器明确允许的页面。

已知主聊天目标是 `doubao://doubao-chat/chat`。设置页面可能是同一渲染目标中的页面状态，也可能是独立目标。开发时必须通过实际 CDP 目标和页面导航观测确定：若是独立目标，将它的地址前缀加入允许列表；若在同一目标内，通过 `settingsPanel` 标记识别。真实设置页面未通过验收前，MVP 不算完成。

明确排除 `doubao://doubao-background/`、`cross-site-support`、登录页和其他辅助渲染器。

## 10. 适配器

只实现一个可替换 JSON 文件，不建设多版本系统。

```json
{
  "adapterVersion": 1,
  "targets": [
    { "kind": "main", "urlPrefix": "doubao://doubao-chat/chat" }
  ],
  "regions": {
    "appRoot": [],
    "sidebar": [],
    "chatArea": [],
    "messageUser": [],
    "messageAssistant": [],
    "composer": [],
    "buttons": [],
    "settingsPanel": []
  },
  "pageStates": {
    "chat": { "requiredRegions": ["appRoot", "chatArea"] },
    "settings": { "requiredRegions": ["appRoot", "settingsPanel"] }
  }
}
```

上例展示 schema，空数组表示尚未填入某区域的实测选择器；发布适配器不允许核心页面所需区域为空。目标地址和选择器必须全部来自当前豆包版本的实测结果。

`pageStates` 明确每个页面状态的必需区域；未列入该状态必需项的区域均为可选。每个语义区域允许按顺序配置少量备用选择器。加载器选择第一个非空匹配，并向匹配节点添加稳定的 `dbs-*` 语义类；主题 CSS 只依赖这些语义类，不直接依赖豆包内部类名。

本地用户适配器存在时优先于内置适配器。MVP 不联网查询或自动更新适配器。

## 11. 注入运行时

主进程连接目标的 CDP WebSocket，启用 `Runtime` 和 `Page`，然后执行构建好的注入载荷。

每个允许页面最多存在：

- 一个固定 ID 的 `<style>` 节点。
- 一个固定 ID 的静态壁纸层。
- 根节点上的 `doubao-skin` 和 `theme-<id>` 类。
- 适配器生成的 `dbs-*` 语义类。
- 一个 `window.__DOUBAO_SKIN_STATE__` 状态对象。

壁纸读取为 Data URL 后在豆包渲染器中转换为 Blob URL。主题切换时复用未变化资源并释放旧 Blob URL。由于 MVP 只支持最大 25 MB 的静态图片，该方式无需本地 HTTP 资源服务。

运行时用防抖 `MutationObserver` 重新标记豆包动态创建的节点；CDP 会话监听页面加载事件并在工具仍运行时重新注入。主题变量变化不刷新页面。

恢复操作必须可重复执行，并完成：

- 删除样式和壁纸节点。
- 移除根主题类、CSS 变量和全部 `dbs-*` 标记。
- 断开观察器和页面监听。
- 释放 Blob URL。
- 删除 `window.__DOUBAO_SKIN_STATE__`。

工具关闭后，已注入皮肤通常会保留到页面重新加载。关闭工具后不保证自动重注入；用户重新打开工具并点击应用即可。MVP 不安装守护程序。

## 12. 本地数据与日志

```text
%LOCALAPPDATA%\DoubaoSkin\
├── themes\
├── adapter\doubao-adapter.json（可选用户覆盖）
├── settings.json
└── app.log
```

预览数据保存在内存中；ZIP 解压使用系统临时目录；不建立持久预览缓存。`app.log` 只记录时间、阶段、错误类型、目标 URL 和选择器匹配计数，不记录对话内容、账号信息或素材内容。日志最大 2 MB，超限时只保留最新内容。

## 13. 错误处理

总原则：皮肤失败时，豆包保持官方界面正常运行。

- 找不到豆包：要求手动选择程序。
- 端口冲突：不结束占用进程，要求更换端口。
- 无调试端口：询问后重启豆包。
- 无允许目标：停止，不尝试后台或未知页面。
- 必需选择器缺失：该页面不注入，状态显示“不兼容”。
- 可选选择器缺失：跳过该区域，其他区域继续。
- ZIP 或主题无效：拒绝导入，不写入用户主题目录。
- `extra.css` 无效：忽略 CSS 扩展，保留标准主题。
- 注入中途失败：执行本次清理逻辑，不关闭豆包。

界面只显示简短状态：“未启动”“需要重启”“正在连接”“已应用”“部分兼容”或“不兼容”。详细信息写入可复制的文本日志，不建设图形化诊断中心。

## 14. 性能与最低环境

- Windows 10/11 64 位。
- 8 GB 内存最低，16 GB 推荐。
- 64 位双核 CPU 最低，四线程以上推荐。
- 普通集成显卡即可。
- 至少 1 GB 可用磁盘空间。
- 1366×768 最低分辨率，1920×1080 推荐。
- 正式安装版不要求用户安装 Node.js、Git 或开发工具。

工具编辑静态主题时的目标内存为 180–280 MB；空闲状态长期超过 500 MB 视为需要修复的性能问题。

## 15. 测试策略

### 15.1 自动测试

- 64×64 量化取色的确定性测试。
- 主题 JSON 合法、缺失字段和不支持版本测试。
- ZIP 导入导出往返一致性。
- ZIP 路径穿越、超限文件和禁止类型拦截。
- `extra.css` 作用域和禁止规则测试。
- 目标 URL 允许/拒绝测试。
- 适配器必需/可选选择器结果测试。
- 注入载荷的幂等应用和清理测试。
- 打包应用启动冒烟测试。

### 15.2 当前豆包版本人工验收

1. 桌面快捷方式能够启动工具和带 CDP 的豆包。
2. 三个内置主题均能应用。
3. PNG、JPG、JPEG 和 WebP 均可创建主题。
4. 自动取色后可用鼠标修改所有 MVP 区域。
5. 聊天页和设置页均能应用主题。
6. 输入、发送消息、滚动、打开会话和设置不受影响。
7. 壁纸和装饰不拦截点击。
8. 导出主题、删除本地副本、重新导入后效果一致。
9. 替换适配器后无需改程序代码即可改变匹配。
10. 一键恢复后没有注入节点、主题类、语义标记、CSS 变量或运行时状态。
11. 后台、登录和辅助渲染器未被注入。
12. 静态主题编辑内存处于 180–280 MB 目标范围。

## 16. MVP 完成条件

只有同时满足以下条件才算完成：

- 生成可安装的 Windows 64 位程序。
- 单窗口完成创建、调色、预览、保存、ZIP 导入导出、应用和恢复。
- 三个版权安全的内置主题可用。
- 当前豆包版本的聊天页和设置页适配器通过真实验收。
- 所有自动测试通过。
- 第 15.2 节人工验收全部通过。
- 提供安装说明、主题格式说明和面向 Agent 的制主题说明。
- 未引入第 2.2 节的排除功能。

## 17. 后续迭代边界

以下内容只能在 MVP 验收后重新设计，不能提前埋入未使用抽象：GIF/视频、开机守护、自动恢复、多版本适配器、在线主题库、字体/图标/动画编辑。后续功能出现第二个真实需求时再扩展当前接口。
