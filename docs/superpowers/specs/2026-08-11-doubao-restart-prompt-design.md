# 豆包皮肤模式重启提示设计

## 目标

让已普通启动的豆包可由皮肤版切换到皮肤模式。用户可选择每次确认关闭，或允许自动关闭重启；也可临时完全停用皮肤自动行为。

## 范围

新增两个持久化设置：

- `confirmBeforeRestart`：默认 `true`。普通豆包占用但没有 CDP 端口时，是否先询问用户。
- `skinTemporarilyDisabled`：默认 `false`。临时停用守护、启动、重启和注入。

设置区显示：

- 自动保持皮肤
- 关闭豆包前询问我
- 暂时停用皮肤

## 设置优先级

1. `skinTemporarilyDisabled` 为 `true` 时，立即停止所有皮肤自动行为；不显示重启提示，不关闭或启动豆包，不注入主题。
2. 否则，`自动保持皮肤` 为 `false` 时不启动自动恢复。
3. 两项均允许时，`confirmBeforeRestart` 决定普通豆包已启动后的处理方式。

停用皮肤不恢复官方外观、不删除已保存主题、不删除壁纸。重新启用后，恢复原自动行为。

## 启动与恢复流程

1. 皮肤版或登录守护启动，读取已保存主题与设置。
2. 皮肤被暂时停用或自动保持关闭时，本轮退出，不操作豆包。
3. 豆包未运行时，以 `--remote-debugging-address=127.0.0.1 --remote-debugging-port=9225` 启动，端口就绪后恢复主题。
4. 豆包已运行且 9225 可连接时，直接恢复主题，不重启。
5. 豆包已运行但 9225 不可连接时：
   - `confirmBeforeRestart=true`：显示确认窗，说明未发送文字可能丢失；用户同意后才关闭重启。
   - `confirmBeforeRestart=false`：自动关闭并以皮肤模式重启。
6. 用户取消确认窗后，本轮不操作；后续状态变化或用户再次点击应用时再检查。

## 关闭与重启

只结束已识别的豆包主进程及其子进程。成功结束后，以保存的豆包启动路径和 CDP 参数启动。等待端口就绪，超时或注入失败时记录失败状态并退避重试；不无限快速循环关闭或启动。

确认文案：

> 豆包未以皮肤模式启动。关闭并重新启动豆包以恢复皮肤？豆包中未发送的文字可能丢失。

按钮：`取消`、`关闭并重启`。

## 例外规则

- 手动“恢复官方外观”会关闭自动保持皮肤，防止守护立即重新注入。
- 删除当前生效主题会关闭其自动恢复状态。
- 已经处于带 9225 的皮肤模式时绝不重启。
- 设置变更立即写入设置文件，重启皮肤版和 Windows 后保留。

## 验收

1. 默认确认模式下，普通豆包启动后显示确认窗；取消不关闭；确认后重启并恢复主题。
2. 关闭“关闭豆包前询问我”后，普通豆包启动时自动关闭、重启并恢复主题。
3. 打开“暂时停用皮肤”后，不提示、不关闭、不启动、不注入；重启 Windows 后仍停用。
4. 关闭“暂时停用皮肤”后，按确认设置恢复自动行为。
5. 恢复官方外观后，守护不自动重新注入。
6. 已带 9225 的豆包恢复主题但不重启。
7. 关闭失败、端口超时、注入失败均显示状态并退避，不反复强杀豆包。
