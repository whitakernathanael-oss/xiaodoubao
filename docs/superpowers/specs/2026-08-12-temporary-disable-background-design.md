# 暂时停用皮肤与后台运行联动设计

## 背景

现有“暂时停用皮肤”只停止守护检测和自动注入，但皮肤工具仍可能保留开机启动入口，并在用户关闭设置窗口后继续驻留后台。这与用户对“暂时停用”的直觉不一致。

本设计把该开关提升为皮肤自动化总开关：停用时不再后台运行；重新启用时，仅在已有可恢复主题的前提下恢复后台检测与开机启动。

## 目标

- 一个开关同时控制守护检测、开机启动入口和关闭窗口后的后台驻留。
- 停用时不删除主题、壁纸或持久化状态。
- 停用时不刷新或移除当前豆包页面中已经显示的皮肤。
- 重新启用后不主动启动豆包，只等待用户启动豆包。
- 没有已保存主题时，不进行没有意义的后台运行。

## 状态规则

| 状态 | 后台检测 | 开机启动 | 关闭设置窗口 |
|---|---|---|---|
| 已有保存主题，未停用 | 开启 | 开启 | 隐藏到后台 |
| 已有保存主题，暂时停用 | 关闭 | 取消 | 完全退出 |
| 没有保存主题，未停用 | 关闭 | 不创建 | 完全退出 |
| 没有保存主题，暂时停用 | 关闭 | 不创建 | 完全退出 |

“已有保存主题”以现有活动皮肤状态能否从 `SkinStateStore` 成功加载为准，不新增第二套状态来源。

## 用户操作

### 勾选“暂时停用皮肤”

1. 立即保存 `skinTemporarilyDisabled=true`。
2. 停止 `SkinGuardian`，取消后续豆包进程探测、提醒、关闭、重启和注入。
3. 删除现有 Windows 开机启动快捷方式。
4. 当前设置窗口保持打开，便于用户查看或重新启用。
5. 用户随后关闭设置窗口时，应用完全退出，不再隐藏到后台。
6. 不调用恢复官方外观，不刷新豆包，不删除活动主题记录。

### 取消“暂时停用皮肤”

1. 立即保存 `skinTemporarilyDisabled=false`。
2. 重新读取现有活动皮肤状态。
3. 如果存在活动皮肤：恢复开机启动快捷方式，并启动后台守护。
4. 如果不存在活动皮肤：不创建开机启动快捷方式，也不启动守护；首次成功应用并保存主题后，再沿用现有流程启用后台守护和开机启动。
5. 守护只等待用户启动豆包；豆包完全关闭时绝不主动启动。

## 进程与窗口行为

主进程的后台驻留条件统一为：

```text
skinPersistenceEnabled
AND activeSkinExists
AND NOT skinTemporarilyDisabled
```

只有三项同时满足时，关闭设置窗口才隐藏窗口并继续后台运行。否则按普通窗口关闭流程退出应用。

本设计不新增系统托盘、Windows 服务、计划任务或注册表启动项。继续复用当前启动文件夹快捷方式和 `--skin-guardian` 后台模式。

## 数据流

```text
用户切换“暂时停用皮肤”
        ↓
Renderer 发送 setSkinAutomation
        ↓
主进程持久化 settings.json
        ↓
┌──────────────────────┬──────────────────────────┐
│ 暂时停用             │ 重新启用                 │
│ stop guardian        │ 读取 active skin         │
│ remove startup link  │ 有主题：安装启动项并守护 │
│ 不恢复官方外观       │ 无主题：保持前台模式     │
└──────────────────────┴──────────────────────────┘
        ↓
窗口关闭逻辑读取新的后台驻留条件
```

## 界面文案

开关名称保持：`暂时停用皮肤`。

说明文案修改为：

> 暂停后台检测与开机启动，不删除已保存主题，也不会立即移除当前豆包皮肤。重新启用后，有已保存主题时恢复后台运行。

开关切换成功后继续使用现有状态提示，不新增弹窗。

## 错误处理

- 删除开机启动快捷方式失败：设置仍保持停用，守护必须停止；界面显示操作失败并记录错误，下一次启动时再次尝试清理。
- 创建开机启动快捷方式失败：不阻止当前会话启动守护，但界面显示操作失败；下一次成功应用主题或重新启用时允许重试。
- 活动皮肤状态损坏或不存在：按“没有保存主题”处理，不启动后台守护，不创建开机启动入口。
- 守护启动失败：不主动启动豆包，不回滚用户的停用设置；返回操作失败。

## 保持不变

- “关闭豆包前询问我”的语义不变。
- 豆包未运行时只做被动检测，不主动启动豆包。
- 恢复官方外观仍是显式操作，不与暂时停用绑定。
- 已保存主题、壁纸和活动皮肤记录在暂时停用时全部保留。
- 没有活动主题时，用户仍可打开设置窗口编辑、导入或应用主题。

## 测试与验收

### 自动化测试

- `setSkinAutomation({ temporarilyDisabled: true })` 停止 guardian 并删除启动快捷方式。
- 停用不调用主题恢复，不删除 `SkinStateStore`。
- 停用时 `persistenceEnabled()` 返回 `false`，关闭窗口不再隐藏后台。
- 重新启用且存在活动皮肤时，安装启动快捷方式并启动 guardian。
- 重新启用但不存在活动皮肤时，不安装快捷方式、不启动 guardian。
- 首次成功应用主题后，按现有流程安装启动快捷方式并启动 guardian。
- 启动后台模式时若设置为停用，不启动 guardian，进程可正常退出。
- Renderer 显示新的说明文案，并保持原开关读写行为。

### 手动验收

1. 已有保存主题时勾选暂时停用：设置窗口保持打开；豆包当前皮肤不消失。
2. 此时关闭设置窗口：任务管理器中豆包皮肤版进程退出。
3. 重启 Windows：豆包皮肤版不自动运行。
4. 手动打开皮肤版并取消停用：恢复开机启动和后台检测，但不主动启动豆包。
5. 普通启动豆包：按“关闭豆包前询问我”的设置接管并恢复主题。
6. 删除活动主题或从未应用过主题：取消停用后关闭窗口，皮肤版完全退出且不创建开机启动项。
7. 首次成功应用主题后关闭窗口：皮肤版隐藏到后台，并在下次开机以守护模式运行。

## 非目标

- 不新增独立的“开机启动”或“后台运行”开关。
- 不新增系统托盘、Windows 服务、计划任务或注册表配置。
- 不在暂时停用时自动恢复官方外观。
- 不修改豆包快捷方式或安装目录。
